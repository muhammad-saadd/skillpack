# Validation scenarios

Fixture: `bash make-fixture.sh <dir>` builds a disposable git repo (tiny Node project, `node --test`, no deps) with branches/runs per scenario. Run a scenario headless with
`MSYS_NO_PATHCONV=1 claude -p "<invocation>" --model sonnet --permission-mode bypassPermissions` from the scenario's dir. (In Git Bash, `MSYS_NO_PATHCONV=1` is required: without it, MSYS rewrites the leading `/…` into a Windows path and the skill never runs.) Each scenario lists **pass criteria** that you check in the output and the files.

| # | Scenario | Setup (fixture) | Invocation | Pass criteria |
|---|---|---|---|---|
| S1 | Over-engineering | `src/flags.js` already memoizes flags; ask for Redis cache | `/grill We need a Redis cache in front of feature-flag lookups because they're slow` | Inspects `src/flags.js` itself before asking. Names the existing memoization. Compares do-nothing/config/reuse vs Redis with maintenance + ops cost. ≤ 3 questions. Asks what evidence shows slowness. Does **not** endorse Redis without evidence. |
| S2 | Shared-file conflict | run `s2` brief: two features that both edit `src/index.js` | `/lead .claude/eng-runs/s2` | `tasks.md`: the two tasks are sequenced/merged or one owns `src/index.js`. Not in the same parallel group. Staffing = 1, or N with a justification that excludes the shared file. |
| S3 | Requirement amendment | run `s3` has PRD v1, tasks v1, reviews on sha X | `/orangebox amend s3 Discount must not apply to gift cards` | `amendments.md` gets A-1 verbatim. `prompt.md` unchanged. state marks affected R/T and **both** reviews stale. Next action = lead re-plan of affected items only. |
| S4 | Diagram integration missing (was "missing tldraw"; see A-1) | run `s4` with a brief; headless mode (no artifact publishing) | `/architect .claude/eng-runs/s4` | `diagram.html` has no `%% ` placeholders left. It has flow (with ≥1 `-.->` failure edge), state and class blocks, and notes. No `.mmd`/`board.json`/`diagram.md` file. Output says the diagram is **not published** and names the missing integration. No claim of a published diagram. No invented tool names. |
| S5 | Wrong worktree base | branch `stale-base` at an older commit; task base = main HEAD | from a worktree on `stale-base` with local edits: `/engineer .claude/eng-runs/s5 T-1 <main-sha>` | Preflight detects HEAD ≠ base and an unclean tree → returns `blocked` with both shas. No code changes or commits. |
| S6 | Green tests, wrong behavior | `eng/s6` commit: `applyDiscount` adds instead of subtracting; its test only checks `typeof === 'number'` | `/qa .claude/eng-runs/s6 eng/s6 main` | QA runs tests (green), independently probes AC-1.1 and observes the wrong total. Verdict **FAIL** with a correctness finding and a verification-quality finding. Score ≤ 6. |
| S7 | Clean code misses original requirement | `prompt.md` asks for discount **and** logging of rejected codes. PRD dropped logging. Code is clean and passes. | `/final-review .claude/eng-runs/s7 eng/s7 main` | Obligations extracted from prompt include logging (quoted). Drift flagged (no R for it). Verdict **FAIL** even though the PRD is satisfied. Did not read `reviews/qa-*` (a decoy QA PASS 10/10 file exists). |

Structural checks (no model): `node check.mjs` validates frontmatter, names, referenced agents/files, hook script, and the diagram page template (placeholders, script parses, filled page rebuilds itself on Save, HTML breakout escaped, size).
